## 1. How to read this document

* **Read vs Write** uses the engine's own `Kind` (`src/skilltrace/dispatch.py:30`): `READ_ONLY` appends no audit event, `MUTATING` appends exactly one event on success (`src/skilltrace/dispatch.py:126`). Both are enforced in `dispatch()` (`src/skilltrace/dispatch.py:110`), not in handlers.
* **JoinedView coverage** names which of `load_context_strict` (`src/skilltrace/context.py:200`) vs `load_context_lenient` (`src/skilltrace/context.py:260`) already supplies the view. The server should reuse the same seam per command's policy (strict = `export`, lenient = `today`/`node`/`next`/reports).
* **Scaffold echo** = what `archive/scaffold-v0.1/interface/` + `archive/scaffold-v0.1/web-app-vision/reference-research-document.md` + ADRs say about the same capability, and whether the server should **reuse** (idea) or **reject** (trap) it, with why.
* Hard invariants repeated throughout: **files-are-truth**, exports are disposable (`src/skilltrace/export_data.py:1`, `src/skilltrace/markdown_export.py`, `src/skilltrace/sqlite_export.py`), asserted progress never demotes (`src/skilltrace/graph/state.py:142`), no hard-prerequisite override, AI review never authority, evidence immutable/supersede-only, `pass_node`/`master_node`/`delete_record` never automated (`src/skilltrace/automation.py:12`, `src/skilltrace/dispatch.py:116`), advisory policies warn/reorder never block.

## 6. Traps to avoid (consolidated from scaffold audit)

1. **No second registry.** Do not reintroduce `commands.yaml`/`interface/` as a server routing table (ADR 0002). `cli.build_parser` + `register_all(Registry())` *is* the registry; the HTTP surface maps to the same callables.
2. **No generic `PATCH /nodes/{id}/state {action}`.** Scaffold's `update-node-state` hides eligibility and hard-prerequisite enforcement. Keep `pass` and `master` as typed, confirmation-gated endpoints.
3. **No planned-session wizard.** Scaffold's `plan-session`/`record-work` vocabulary (`kind`, `goal`, `minutes_spent`) conflates sessions with work logs; the engine's templates are opaque (`execution/templates.py:28`). Reuse `start`/`work` semantics.
4. **No pending acceptance queue.** Evidence acceptance is frozen at submit (ADR 0003); there is no "pending evidence to approve later." A failing objective gate yields a *written* rejected record, not a refusal.
5. **No progress mutation from interface cards / UI state files.** `interface/cards.yaml` + `state.yaml` are reference-only (`docs/adr/0005-scaffold-retirement.md:21`); `archive/scaffold-v0.1/` never read by the engine at runtime.
6. **Eligibility and resource status are derived, never stored or recomputed in browser.** Superseded records, mastery spacing, and `stale`/`verified` are server-derived facts; the browser consumes them, never recalculates them from partial JSON.
7. **No validation fence before every mutation.** Scaffold's `requires_validation_first:true` on 12+ commands is advisory (scan) — reads/writes succeed unless hard boundaries fail; `health` is independent.
8. **No SQLite/HTML re-consumption.** `data/skilltrace.db` and `data/export.md` are disposable exports (`export_data.py:1`); `serve` reads `graph/*.yaml` etc., not the mirror.
9. **No auth / hosted / multi-learner surface.** `CONTEXT.md: Single learner`, `localhost` only per map Notes — `serve` binds loopback, no login.
10. **No new dep without a decision.** Current `PyYAML` only (`pyproject.toml`); any web framework/server dep is a Wayfinder decision (map Notes).
