CLI Invocation Architecture Trade-offs

Option 1: Unified Subcommand Family

RECOMMENDED

Group all analytical views under skilltrace report <target>.

skilltrace report progress
skilltrace report blockers
skilltrace report reviews
skilltrace report evidence [--node-id <id>]
skilltrace report resources

Pros: Mirrors validate <layer> and export <target>. Clear distinction between daily fast listings (skilltrace blockers) and deep analytical reports. Top-level aliases like st progress can be added cleanly via #32 alias policy.

Option 2: Flags on Existing Listings & Top-Level

Spread across listing flags and top-level domain commands.

skilltrace progress
skilltrace blockers --report (or --all)
skilltrace reviews --report (or --all)
skilltrace evidence report [--node-id <id>]
skilltrace resource-report

Cons: Inconsistent mental model. Mixes top-level commands, subcommands, and flags. Harder to discover in --help.
