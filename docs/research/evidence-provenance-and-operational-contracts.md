# Evidence provenance and operational contracts for SkillTrace

**Research date:** 2026-09-03
**Scope:** Review-to-evidence semantics, reproducible practice, provenance, graph validation, scheduler contracts, diagnostics, portability, plugins, synchronization, privacy, and metrics. This is an additive decision note, not a redesign.

**Primary-source corpus:** [`S-Sigdel/vimhjkl@501762f`](https://github.com/S-Sigdel/vimhjkl/tree/501762feecd0aa1c2f04089ba2f94177159b730e), [`mnemosyne-proj/mnemosyne@ff4f61e`](https://github.com/mnemosyne-proj/mnemosyne/tree/ff4f61e84bea0d6928c29b7798f0f88b90938a0a), [`ankidroid/Anki-Android@789816b`](https://github.com/ankidroid/Anki-Android/tree/789816b6e4119dc601486f37cc9b42f879f550a1), and [`in-toto/attestation@2dcd055`](https://github.com/in-toto/attestation/tree/2dcd055e9f72e746687c306e35f4e59720ff45be). Existing notes in `docs/research/` establish these as closest comparators; this follow-up reads pinned upstream source and behavioral tests, not secondary descriptions. Local claims cite the current SkillTrace tree (HEAD `61f54164a50ed76b2481f270cb6abc2841e26265`). Every external URL is commit-pinned and each cited range was verified.

## Baseline to preserve

SkillTrace separates acceptance from progress. A manual or objective gate produces an accepted/rejected `EvidenceRecord`; a gate that cannot run produces no record. The pure planner freezes verdict, authority, artifact hash, and submission time (`src/skilltrace/evidence/submission.py:147-217`). The frozen, closed record schema admits only `objective_gate` and `learner_manual`, and the test suite rejects `ai_review` (`src/skilltrace/evidence/records.py:24-77, 100-155`; `tests/evidence/test_records.py:73-86`).

Eligibility is derived, but passing remains an explicit learner action. Integration tests prove a locked node refuses despite eligible evidence, refusals write no state/event, and `commands/pass_.py` is the sole production writer of `passed` (`tests/evidence/test_pass_command.py:90-145, 227-247`). The store refuses derived writes to asserted progress and asserted backward transitions (`src/skilltrace/graph/state.py:110-154`); the glossary reserves pass/master for learners, requires supersession instead of evidence mutation, and makes AI advisory-only (`CONTEXT.md:30-49, 118-178`).

Graph validation already checks duplicate IDs, all endpoints including inactive edges, active hard-edge cycles, dangling progress, and advisory soft-edge cycles (`src/skilltrace/graph/validation.py:91-146`). Readiness derives only from active hard prerequisites and skips asserted states (`src/skilltrace/graph/readiness.py:47-115`). Recommendation is pure, deterministic, limited to `available`/`active`, and can explain locked prerequisites (`src/skilltrace/graph/recommendation.py:204-276`; `tests/graph/test_recommendation.py:61-93, 186-208`).

Retention takes an injected clock, sorts history deterministically, derives suggestions, and never writes (`src/skilltrace/policy/retention_model.py:1-28, 103-187`). v1.6 derives review completion and evidence coverage from truth files, but coverage currently means one accepted, non-superseded record for each required spec, not satisfaction of every `minimum_count` (`src/skilltrace/analytics/derive.py:274-428`; `src/skilltrace/evidence/submission.py:111-126`). Events are audit-only and appended after successful mutating commands (`src/skilltrace/events.py:1-55`; `src/skilltrace/dispatch.py:127-154`). The roadmap keeps Markdown/YAML as truth and scopes sync to readiness recomputation (`docs/skilltrace-application-roadmap.md:29-67`; `docs/POST_V1_ROADMAP.md:29-50, 66-76`).

## External findings

### Reproducible practice and review-to-evidence semantics

`vimhjkl` grades procedure against observable final state: cursor location plus unchanged buffer, expected register plus unchanged buffer, or expected output buffer; selected drills also require an Ex command. Its result preserves keystrokes and efficiency ([`grader.py:429-500`](https://github.com/S-Sigdel/vimhjkl/blob/501762feecd0aa1c2f04089ba2f94177159b730e/src/vimhjkl/grader.py#L429-L500)). Its content build replays each authored solution, rejects aborts, incorrect results, no-ops, and unmotivated scopes, and writes observed keystrokes as the par ([`generate.py:34-102`](https://github.com/S-Sigdel/vimhjkl/blob/501762feecd0aa1c2f04089ba2f94177159b730e/build/generate.py#L34-L102)).

**Assessment:** Separating authored-fixture verification from learner-artifact verification is a useful pattern for an objective SkillTrace gate. It must stay beneath the present boundary: current gate output decides an EvidenceRecord verdict only (`src/skilltrace/evidence/submission.py:178-217`), while learner-only pass/master remain explicit (`CONTEXT.md:118-139`).

### Provenance

The in-toto statement implementation rejects a statement lacking subject, subject digest, predicate type, or predicate ([`statement.go:15-57`](https://github.com/in-toto/attestation/blob/2dcd055e9f72e746687c306e35f4e59720ff45be/go/v1/statement.go#L15-L57)). Its Link predicate carries a step name, command, input materials, byproducts, and environment ([`link.pb.go:26-35`](https://github.com/in-toto/attestation/blob/2dcd055e9f72e746687c306e35f4e59720ff45be/go/predicates/link/v0/link.pb.go#L26-L35)); its provenance validator requires build type, external parameters, resolved dependencies, builder identity, and run details ([`provenance.go:14-137`](https://github.com/in-toto/attestation/blob/2dcd055e9f72e746687c306e35f4e59720ff45be/go/predicates/provenance/v1/provenance.go#L14-L137)).

**Assessment:** SkillTrace freezes an artifact hash but does not retain a gate execution recipe such as resolved command, working-directory basis, tool identity/version, declared inputs, exit class, or bounded diagnostic output (`src/skilltrace/evidence/submission.py:183-217`; `src/skilltrace/evidence/records.py:24-55`). That is a provenance-completeness gap for future reproducible gates, not a reason to make gates progress authorities.

### Scheduler contracts and diagnostics

Mnemosyne's scheduler contract explicitly includes queue rebuild/invalidation, membership/removal, next-card selection, prefetch permission, grading, counts, and schedule projection ([`scheduler.py:65-119`](https://github.com/mnemosyne-proj/mnemosyne/blob/ff4f61e84bea0d6928c29b7798f0f88b90938a0a/mnemosyne/libmnemosyne/scheduler.py#L65-L119)). AnkiDroid serializes collection access on a one-parallelism IO dispatcher and explains that suspendable blocks could otherwise interleave requests ([`CollectionManager.kt:77-147`](https://github.com/ankidroid/Anki-Android/blob/789816b6e4119dc601486f37cc9b42f879f550a1/anki-common/src/main/kotlin/com/ichi2/anki/CollectionManager.kt#L77-L147)). Its scheduler tests specify that fetching does not change counts but answering does ([`SchedulerTest.kt:932-1004`](https://github.com/ankidroid/Anki-Android/blob/789816b6e4119dc601486f37cc9b42f879f550a1/libanki/src/test/java/com/ichi2/anki/libanki/SchedulerTest.kt#L932-L1004)).

**Assessment:** SkillTrace should not import a card queue. However, a future concurrent Serve, plugin, or multi-process writer needs the narrower contract: mutation owner, stale-write behavior, reader refresh, and whether a failed write consumes work. Existing pure recommendation and clock-injected retention avoid that complexity (`src/skilltrace/graph/recommendation.py:204-276`; `src/skilltrace/policy/retention_model.py:153-187`).

### Plugins and synchronization

Mnemosyne allows multiple components for some roles but selects the last registered component where only one may be active ([`component_manager.py:5-48, 82-137`](https://github.com/mnemosyne-proj/mnemosyne/blob/ff4f61e84bea0d6928c29b7798f0f88b90938a0a/mnemosyne/libmnemosyne/component_manager.py#L5-L48)). A plugin can install a scheduler, review controller, or review widget and trigger review reset; deactivation refuses when its card type remains represented in storage ([`plugin.py:49-145`](https://github.com/mnemosyne-proj/mnemosyne/blob/ff4f61e84bea0d6928c29b7798f0f88b90938a0a/mnemosyne/libmnemosyne/plugin.py#L49-L145)). Its sync metadata tracks partner watermarks, streams later log entries, and refuses completion if a needed card-type plugin is absent ([`SQLite_sync.py:35-46, 67-166`](https://github.com/mnemosyne-proj/mnemosyne/blob/ff4f61e84bea0d6928c29b7798f0f88b90938a0a/mnemosyne/libmnemosyne/databases/SQLite_sync.py#L35-L46)). Its client makes backup, full transfer, incremental transfer, media transfer, conflict resolution, and recovery distinct steps ([`client.py:141-252`](https://github.com/mnemosyne-proj/mnemosyne/blob/ff4f61e84bea0d6928c29b7798f0f88b90938a0a/openSM2sync/client.py#L141-L252)).

**Assessment:** Plugins and remote sync are semantic authorities unless constrained; they cannot be mere alternate file readers. SkillTrace properly confines current sync to readiness and defers cloud sync (`src/skilltrace/graph/readiness.py:82-115`; `docs/POST_V1_ROADMAP.md:66-76`). A future extension must not become an alternate asserted-progress writer or edge source.

### Privacy, portability, and metrics

Mnemosyne logs lifecycle and scheduler counts; repetition logs include grade, easiness, repetition/lapse counts, intervals, thinking time, next repetition, and scheduler data ([`SQLite_logging.py:29-58, 98-111`](https://github.com/mnemosyne-proj/mnemosyne/blob/ff4f61e84bea0d6928c29b7798f0f88b90938a0a/mnemosyne/libmnemosyne/databases/SQLite_logging.py#L29-L58)). AnkiDroid sends usage data only after opt-in ([`AnkiDroidUsageAnalytics.kt:28-35, 148-152, 181-224`](https://github.com/ankidroid/Anki-Android/blob/789816b6e4119dc601486f37cc9b42f879f550a1/AnkiDroid/src/main/java/com/ichi2/anki/analytics/AnkiDroidUsageAnalytics.kt#L28-L35)), isolates an install-scoped client ID, and bounds exception text ([`AnkiDroidUsageAnalytics.kt:41-57, 211-231`](https://github.com/ankidroid/Anki-Android/blob/789816b6e4119dc601486f37cc9b42f879f550a1/AnkiDroid/src/main/java/com/ichi2/anki/analytics/AnkiDroidUsageAnalytics.kt#L41-L57)). AnkiDroid's count tests also make metric semantics executable rather than presentation-only ([`SchedulerTest.kt:943-975`](https://github.com/ankidroid/Anki-Android/blob/789816b6e4119dc601486f37cc9b42f879f550a1/libanki/src/test/java/com/ichi2/anki/libanki/SchedulerTest.kt#L943-L975)).

**Assessment:** SkillTrace events retain local command arguments and record IDs (`src/skilltrace/events.py:29-55`), so local-first is not equivalent to non-sensitive: paths, notes, arguments, and blocker/review text can leak in portable output. v1.6 correctly remains read-only over primary YAML (`docs/spec-v1.6-event-log-analytics.md:49-81, 145-171`), but a metric must name its denominator and must not claim pass eligibility from required-spec presence.

## Ranked open questions and additive guardrails

Rank is by impact, then reversibility. `Low` reversibility means a wrong decision is hard to unwind after records or integrations exist. None of these guardrails permits automated passing/mastering, evidence mutation, asserted-state demotion, hard-prerequisite override, alternate edge truth, or derived data becoming truth.

| Rank | Material question | Impact | Reversibility | Additive guardrail |
| --- | --- | --- | --- | --- |
| 1 | What must an objective gate preserve so a learner can reproduce/explain its verdict? | High | Low | Before reproducible gates, define an optional immutable **gate-run receipt** on a new EvidenceRecord: normalized command identity, declared root-relative inputs, available runner/tool version, exit class, and hashes of retained outputs. Exclude secrets, arbitrary environment values, and unbounded logs by default. Receipt context cannot pass/master. |
| 2 | What is the single-writer contract for simultaneous CLI/Serve/plugin mutations of one repository? | High | Low | Before a concurrent writer ships, specify repository-scoped serialization, reload-after-success, and stale-write refusal/diagnostic behavior. All asserted-progress writes still route through core dispatch. |
| 3 | What semantic conflict matrix is required before multi-device sync is reopened? | High | Low | Keep remote sync out of scope. Require a written matrix for immutable records, supersession heads, learner assertions, graph/policy edits, artifacts, and missing plugins before accepting any transport prototype. `sync` remains readiness-only. |
| 4 | Which plugin capabilities are safe without an alternate authority path? | High | Medium | Start with declarative/versioned importer, renderer, advisory analyzer, artifact producer, and objective-gate adapter capabilities. Require core validation/dispatch for writes; prohibit direct asserted-progress writes, edge mutation, or authority registration. Pin relied-on plugin identity/version in a future receipt. |
| 5 | How should a graph edit report learner impact beyond topology validity? | Medium | Medium | Add a read-only optional graph-impact diagnostic before curriculum releases: newly locked/unlocked *derived* nodes, recommendation changes, dangling evidence/spec references, and no-op edges. It reads relationships only from `edges.yaml` and treats asserted states as immutable. |
| 6 | Should authored-fixture verification be distinct from learner-artifact verification? | Medium | Medium | Keep fixture verification in curriculum validation/build tooling and learner verdicts in evidence submission. Use structured categories for unrunnable, invalid fixture, failed artifact, and unavailable diagnostics; only submission writes learner evidence. |
| 7 | Which fields may leave the repo in reports, support bundles, backups, plugins, or future telemetry? | High | Medium | Before outbound functionality, establish a default-deny share profile: explicit field selection, default redaction of paths/free text, separately documented opt-in telemetry, local sampling, and deletion/retention statement. This does not make local records less truthful. |
| 8 | Must required-spec presence coverage and pass-eligibility coverage have separate names? | Medium | High | Retain v1.6 coverage but label it **required-spec presence coverage**. If readiness-to-pass reporting is wanted, add separately named read-only eligibility coverage with an explicit denominator/data threshold. Neither metric transitions state or changes recommendations without separate advisory-policy law. |
| 9 | Which diagnostics are stable and safe enough to retain? | Medium | High | Define tiers before preserving gate output: summary/hash by default, opt-in bounded sanitized excerpt, explicit local artifact attachment. Test that diagnostic failure is not a verdict failure and unrunnable remains no judgment. |
| 10 | What does an evidence location mean after a checkout move, Windows path change, or another machine? | Medium | High | Preserve today's location as history. Add portability only through an optional root-relative locator plus content hash and external URI/identifier. A missing moved artifact is a health warning, never retrospective unacceptance or demotion. |

## Non-negotiable guardrails

- A verifier, scheduler, plugin, sync process, metric, or AI may provide evidence, diagnostics, or advice, but cannot pass/master a node (`CONTEXT.md:118-164`; `tests/evidence/test_pass_command.py:227-247`; `tests/policy/test_master_command.py:16-58`).
- Corrections remain new independently judged records with a supersession reason; an asserted pass survives an eligibility discrepancy (`src/skilltrace/evidence/submission.py:220-298`; `CONTEXT.md:165-178`).
- `edges.yaml` remains the only relationship source; malformed hard dependencies fail; sync never writes asserted progress (`CONTEXT.md:72-90`; `src/skilltrace/graph/validation.py:91-146`; `src/skilltrace/graph/readiness.py:82-115`).
- Markdown/YAML remain local truth. Events, exports, analytics mirrors, and portable forms remain derived and are never read back for learner state (`docs/skilltrace-application-roadmap.md:46-67`; `src/skilltrace/events.py:1-55`; `src/skilltrace/export_data.py:1-75`).

## Conclusion

The material additive opportunity is a small immutable provenance receipt for objective practice, not an imported card scheduler or AI authority. The highest-risk decisions are future-facing: serialized local writes, semantic conflicts before remote sync, and capability-scoped plugins. Clear metric names and a portable-diagnostics privacy contract can then improve interpretation without changing acceptance or progress authority.
