## A-Landed — resolution

Evidence: [.svc_fetch.txt](./.svc_fetch.txt) — the landed v2.4 home (`/`), `/next`, `/health`, `/analytics`, and the 404s on `/nodes/jump` and `/nodes/a-very-compact-node-id-offset`, fetched live from `skilltrace serve --port 8395 --no-browser` on `main` (`c097ef9`).

**Landed home, verbatim:** one `<div class="card focus">` (the focal node, titled, with its `Active` pill, "Where to learn," and one primary affordance) + one `<div class="card counts">` ("48 ready," "1 day practiced") + one pointer to `/next`. That's the page. The focus card does name the node — so the "current focus, named" row is satisfied at the home level — but every other piece of the single-page richness the owner expected is either absent on `/` or pushed to another route.

**The seven-element gap inventory** is in the artifact. In short: (1) the available-node board is not on the page; (2) the node title is named (satisfied); (3) only the focal card's state is shown, not the set; (4) the graph spine / "what unlocks what" is not on the page; (5) the queue and pressure live on `/next`, not home; (6) the daily count set did land; (7) the health presence is a header alert, not a calm-line card.

**The two user-friendly-surface questions, answered and routed to the prototype ticket:**
- **Sessions stored and viewable?** Yes — persisted as YAML in `execution/sessions.yaml`, `session_work.yaml`, `blockers.yaml`, `reviews.yaml`, `remediation_actions.yaml`. The data exists. But there is **no web surface** for session history; the web only shows the session *count* on `/health` (live output: `1 sessions, 1 work items, 0 blockers, 0 remediation actions, 0 reviews`). "How much did I study, and what did I do" belongs on a richer home or a history card.
- **Friendlier node view than the long flat list?** The web renders nodes in two list-shaped places only — the `/next` ranked queue and the per-node `/nodes/{id}` detail — with **no** graph/tree/map visualization; relationships live in `graph/edges.yaml` (157 edges per `skilltrace health`) but are never rendered visually. This is deliberate (ADR 0006 stdlib-only; G-JS #225 tier-0, JS budget = 0; #208 refused graph-viz libraries; legibility by abstraction). The right vehicle for "friendlier" is the unified-page prototype's card inventory on [#246](https://github.com/earledotpy/skilltrace/issues/246), where these become candidate cards: a session-history card and a spine/pathway card + a filterable/groupable available-node view — tier-0 abstractions, not a visual graph dump.

**Why it felt stripped down:** the landed home is the P3 card-stack as the spec locks it (focus + count set + pointer), with the queue/pressure/detail/spine deferred to other routes. That's the same family of rows — P1.1 named-once, P1.2 bounded day, P5.3 density cap, §A's P1-base ruling — that made "all information on one page" into "one focal card + pointer." This audit exists so #247 can amend those rows knowing what they cost.

**Resolution verdict:** the landed UI is faithful to the locked spec; the owner's dissatisfaction is with the locked direction itself, now documented element-by-element and routed to the re-direction chain (#246 → #247 → #248 → #249 → #250).
